Contexto

Um sistema web em que a equipe audita propostas de crédito, organizadas em filas de trabalho que o próprio sistema monta.

Se o sistema saísse do ar ou parasse de montar as filas, a equipe só descobria quando tentava trabalhar.

O desafio

Saber durante o expediente se o sistema está no ar e se as filas continuam sendo montadas, sem alguém precisar entrar para conferir.

Como funciona

Durante o expediente, duas verificações rodam em paralelo:

Agenda do horário comercialdas 8h às 18h
Conferência rápidaa cada 5 minutos: o sistema responde?
Teste completoa cada 1 hora: as filas são montadas?

Painel do time
Jira

O que eu fiz

  • Criei a conferência rápidaA cada 5 minutos, um teste checa se o sistema responde.
  • Testei o que importaUm teste entra no sistema, pede para montar as filas de propostas e confere a mensagem de confirmação.
  • Respeitei o expedienteOs testes rodam das 8h às 18h, quando a equipe usa o sistema.
  • Montei a agendaFila, histórico, vídeos e controles para rodar, parar e editar cada teste.
  • Liguei ao restoA agenda usa o mesmo painel e o mesmo Jira dos testes do aplicativo.

Antes e depois

Antes

  • Problemas descobertos por quem tentava usar
  • Ninguém conferia o sistema ao longo do dia
  • Sem histórico do que aconteceu

Depois

  • Conferência a cada 5 minutos
  • Montagem das filas testada a cada hora
  • Histórico e vídeos no painel

O que aprendi

Rodar os testes só no horário em que as pessoas trabalham deixa os avisos úteis e evita alarmes de madrugada sem ninguém para agir.

O código e os dados são da empresa e não podem ser publicados. No meu projeto público, uma loja de demonstração tem 5 conferências separadas a cada 5 minutos, das 8h às 18h, no mesmo formato.
